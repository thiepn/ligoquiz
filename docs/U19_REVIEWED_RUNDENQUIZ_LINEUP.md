# U19 — Custom reviewed Rundenquiz question lineup

The original approved program finder (U18) could select a game and profile but could not select **which questions** in an approved Rundenquiz bank were used. The original selector takes the first available questions in each round, so a host preparing a different evening had no way to replace one approved source question without changing the bank or code.

U19 implements **Fragen für den Abend** inside \`#/setup\` → Programm, only when choosing **Rundenquiz** with a **redaktionell freigegebene** source. A host explicitly selects automatic original order or switches to a manual question lineup. Questions are shown **by the original canonical round**, with exact \`PROFILE_COUNTS\` quotas: Wissen, vier Hinweise, Schätzen and Finale (0 for Kurz). Checkbox selection is bounded by each round quota; a completed exact selection advances, while an incomplete selection blocks the next setup step. The selection persists **inside the original bounded setup draft** across reload and is cleared whenever game/profile/source changes. No new localStorage key/store or separate editor.

The displayed choices come only from existing approved \`ContentRepository\` entries that pass their original \`validatePayload\` rules and cryptographically match the original editorial SHA-256 fingerprint. The visible list includes only ID, round, and organizer-only question prompt—**never the answer, solution, reference, or private notes**, and it does not publish or change stage frames.

The original \`createPreparedApproved\` still performs all content retrieval, CAS-gated event creation, ownership, source freezing and fingerprint checks. In its Rundenquiz case only, when an explicit selection exists, U19 filters to precisely the approved IDs and calls the existing \`selectReviewedPack\` and \`createSession\`. It fails closed for incomplete, duplicate, missing or revoked selections. The frozen event preserves exactly the user-picked original task IDs, original source fingerprints and canonical round/game ordering. Automatic selection and **all four other game engines** retain exactly their former path. After selection, an approval can change in another tab; original final freeze still fails rather than substituting a trial question.
