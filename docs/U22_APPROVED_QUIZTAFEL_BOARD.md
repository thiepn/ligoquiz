# U22 — Reviewed Quiztafel board composition (bounded original workflow)

## Distinct original-game gap
U18 identifies playable approved banks and U19 lets organizers curate **Rundenquiz** question order. The original **Quiztafel** still selected the first approved categories sorted by source ID and the first approved question at each point value; organizers could not assemble a different actual board even if the original content library contained reviewed alternatives. U22 closes that Quiztafel-specific gameplay-preparation gap, without adding a new board engine or content library.

In original local \`#/setup\` step **Programm**, only for **Quiztafel + redaktionell freigegebene Inhaltsbibliothek**, organizers can use **Automatische Originaltafel** (100% existing behavior) or **Spielfeld selbst zusammenstellen**. The manual form shows original approved categories with source-authored public prompts and one selectable question per 100–600-point row depending on the original \`DEPTH[profile]\`. Select exactly the team's number of categories (3–5), each complete with one source-backed question at every value; when the maximum categories are active, other categories are disabled until selection is freed. Multiple original questions for the same category/row are actual selectable alternatives, not duplicated cards.

The UI instantly shows **categories / teams** and **selected cells / required cells**. An incomplete, duplicated or structurally invalid manual board cannot advance to the final ready screen. All selected original content IDs are saved inside the existing bounded setup draft as \`qtTileIds\`, preserving mobile reload continuity with no extra browser keys, IndexedDB or scheduler. Changing game, content source, profile or team count clears the old manual board; reverting to automatic selection restores the exact original choice behavior.

## Actual approved source and gameplay authority
\`reviewedQuiztafelChoices\` reads the original \`ContentRepository\` in the organizer setup only. A candidate must have the original **approved** state, a real receipt, a valid canonical Quiztafel schema and a SHA-256 matching its source review fingerprint; tampered, unreviewed or quarantined items are excluded. The local editor projects only original source IDs, category names, point values, and visible prompts—**not answers, source notes, moderator data, or scoring**.

At the final host action, \`createPreparedApproved\` rereads original content. For manual Quiztafel it filters to **exactly** the user's original selected approved IDs and passes them into existing \`selectReviewedPack\` (which invokes \`verifyBoard\`), then original \`qtSession\`, \`freeze\`, SHA verification, and event CAS persistence. Non-manual Quiztafel and **all other four game engines** follow their original unmodified paths. A selected question revoked or modified in another tab fails closed; no supplemental trial tiles, inferred answers, or shadow approvals are added.
