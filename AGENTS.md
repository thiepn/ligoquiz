# LiGoQuiz — functional UI copy

Applies to the V2 five-game application, including desktop, mobile, organizer, host, public projector, results and backstage.

## No decorative microcopy
- Visible text must identify a game, real rule, actionable control, actual content/data, state, error, feedback, consent, privacy, rights, accessibility or task-essential instruction.
- Omit promotional subtitles, ornamental headings, redundant helper text, duplicate phase summaries, decorative captions and tiny filler on cards, buttons, modals and screens.
- Remove unnecessary rendered JSX and its surrounding layout; never merely hide filler with CSS or replace it with different filler.
- Keep readable supporting text (normally 14px or larger) and the expressive, playful Studio Pop game-show identity; no muted dashboard redesign.

## Original authority and safety
- The HostGameplayRail and HostModerationGuide already display live phase and next action. Do not add a third phase card in each game host.
- Preserve the five original engines, explicit decisions, point previews/commits, event revision/CAS, source IDs and rights, human moderation, offline/local ownership, and original recovery and backup workflows.
- Never leak host-only answers to public projection, conflate a connected window with a checked beamer, or represent trial content as approved.
- Retain game rules, source provenance, privacy warnings, public-stage connection/refusal/pause statuses and V2.0 NO-GO release gates.

## Qualification
- Audit every affected route and responsive state before changes; adapt source, keyboard and original browser tests for intentional copy changes.
- Separate successfully run tests from source readback and not-tested items. Never claim browser tests passed because test files exist.
- No merge, deployment, score/state/rights changes or new release claims as part of UI copy hygiene without express authorization.
